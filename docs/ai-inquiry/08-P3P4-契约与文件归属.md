# P3 / P4 契约与文件归属（2026-11-22 派工）

> 本文件是并行施工的唯一对齐物。子代理互相看不到对方的文件与本对话，**一律以本文件为准**。

## 目标

**P3｜车型必须按车型库配置讲**
AI 助手（`/api/agent-chat` 的 `match_vehicles` 工具）讲车型时，车型名、载重、车长、轴型**全部来自引擎 `/reference/vehicle-models`（46 款）**，不许模型推断或改写。
现状缺口：`FleetGroup` 只有 `model / category / vehicle_count / reason / flags`，模型拿不到载重与车长，只能含糊其辞。

**P4｜内部版看配车明细**
`/quote/internal` 能看四约束分解（`breakdown`）、轴荷线（`axle_lines`）、共车组合（`pairs`）、运输单元数（`transport_units`）。
公开版 `/quote` **永久不返回**这些字段（成本与桌面工作台口径红线）。

## 字段契约

### A. `VehicleSpec`（sa-1 实现，其余两路照此消费）

```ts
export type VehicleSpec = {
  model_id: string;
  display_name: string;
  category: string;
  max_load_ton: number;          // 吨
  length_m: number;
  width_m: number;
  height_m: number;
  max_cargo_height_m: number | null;
  loading_efficiency: number | null;
  curb_weight_ton: number | null;
  floor_area_m2: number | null;
  effective_volume_m3: number | null;
  axle_config: string | null;    // 如 'TR-02' / '6×4'
  suitable_cargo_types: string[];
};
```

数据源：`engineJson('/reference/vehicle-models')`（`server/tools/engineClient.ts` 已导出），响应形状：

```jsonc
{ "<category>": [ { "model_id": "…", "display_name": "…", "max_load_ton": 30,
                    "volume_capacity_m3": 0, "length_m": 13, "width_m": 2.5, "height_m": 1.5,
                    "max_cargo_height_m": 3.2, "loading_efficiency": 0.9, "curb_weight_ton": 15,
                    "floor_area_m2": 32.5, "effective_volume_m3": 104,
                    "base_rate_vnd_per_km": 99999, "fuel_l_per_100km": 40, "fuel_penalty": 0,
                    "fixed_surcharge_vnd": 1, "toll_rate_vnd_per_km": 1,
                    "osrm_profile": "driving", "axle_config": "TR-02",
                    "suitable_cargo_types": ["normal"], "notes": "内部备注" } ] }
```

**红线（sa-1 硬约束）**：`VehicleSpec` 里**永远不许**出现
`base_rate_vnd_per_km / fuel_l_per_100km / fuel_penalty / fixed_surcharge_vnd / toll_rate_vnd_per_km / notes`
—— 前五个是成本单价，`notes` 含供应商备注。类型层面就不给这些字段留位。

失败语义：引擎不可达/超时/形状不对 → **返回空 Map，不许抛**（调用方 `rebuild` 会把 `spec` 置 `null`）。

### B. `match_vehicles` 工具（sa-2）

- 工具 `description` 追加一句：**「车型名与参数一律取自车辆型号库，禁止自行推断或改写车型名」**
- 工具返回给模型的 JSON：每组带 `display_name / max_load_ton / length_m / axle_config`（从 `spec` 取，`spec` 为 null 时只给 `display_name` 与 `max_load_ton`）
- 面向用户的 summary 文案带「库内车型名 + 载重 + 车长 + 车数」
- **不许**把 `spec` 里的原始对象整块塞给模型（会把 31 列全暴露，含无关字段）—— 逐键挑上述 4 个

现有类型（已生效，直接消费）：

```ts
type FleetGroup = {
  model: string; display_name: string; category: string;
  max_load_ton: number; vehicle_count: number; reason: string;
  flags: string[]; spec: VehicleSpec | null;
};
```

### C. 内部版 `/fit`（sa-3）

- `POST /api/quote/fit` 现有公开行为**一个字段都不许变**
- 加内部版分支：请求头 `x-quote-key` 校验通过时，返回下列形状（**逐键显式赋值，不 spread 引擎对象**）

```ts
export type InternalFit = {
  ok: true;
  scope: 'internal';
  total_trucks: number;
  needs_split: boolean;
  split_note: string;
  note: string;
  /** A6 可解体件拆件建议（顶层，不属于任何一组）；非可解体件或本就不超限时为 null */
  divisibility: Record<string, unknown> | null;
  groups: Array<{
    model_id: string;
    display_name: string;
    category: string;
    max_load_ton: number;
    vehicle_count: number;
    transport_units: number;
    reason: string;
    dim_flags: string[];
    permit_flags: string[];
    oversize_released: boolean;
    count_doctrine: Record<string, unknown>;
    axle_lines: Record<string, unknown> | null;
    breakdown: Record<string, unknown>;
    pairs: Array<Record<string, unknown>>;
  }>;
};
```

> `divisibility`：引擎 `/reference/fit-vehicles` 顶层字段（2026-11-22 新增透出，源自 `FleetPlan.divisibility` / A6）。
> 语义提醒：拆件通常不是「避开超限」，而是把三类（15 工作日 + 护送）降到一类（2 工作日）。
> **公开版永远不许出现这个字段。**

以上组字段在引擎 `/reference/fit-vehicles` 响应里**都已存在**（见 `app/api/reference.py` 的 `_group_out`），不需要改引擎。

> **实现时实际落了 15 个组字段**：契约类型列的是 14 个，sa-3 额外保留了引擎确有的 `pair_total_width_m`
> （共车组合总宽，非成本口径）。`scripts/verify-quote-internal-fit.py` 的断言只查「缺不缺」不查「多没多」，
> 多这一个键属于可接受的信息量，不再回退。
>
> **不带** `items` / `locked`：前者是逐行明细、后者是桌面版逐行锁定态，内部版只到「组」这一层。

### C-2. A6 可解体建议在单件货上的修复（2026-11-22，引擎侧）

引擎 API 层用 `_planner = plan_fleet_by_item if len(items) >= 2 else plan_fleet` 分流 ——
而 A6 的 `divisibility` 原本**只在 `plan_fleet_by_item` 里计算**，于是**单件大件永远拿不到拆件建议**，
偏偏可解体件最常见的正是单件（实测：30 m 塔筒 `divisible=true` → `divisibility: null`）。

已修：`plan_fleet()`（整票试算这条路径）在构造 `FleetPlan` 前补同一段 `divisibility_advice()`，
并把结果传给 `FleetPlan(divisibility=_div)`。修后实测：

```
e1（divisible=true）: {"divisible": true, "split_pieces": 2,
   "whole": {"trucks": 1, "tier": "三类"},
   "split": {"trucks": 2, "piece_length_m": 15.0, "piece_weight_ton"…
              "tier": "一类", "workdays_local": 2}}
e2（不带 divisible）: null
```

引擎回归：`pytest` **737 passed, 1 xfailed**（零回归）。

校验方式沿用本文件既有写法（`internalDenied(req)` / `x-quote-key` 判断，见 `quoteProxy.ts` 第 360、798 行附近），**不要新写一套鉴权**。
