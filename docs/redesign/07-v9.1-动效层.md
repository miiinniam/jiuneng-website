# 07 · v9.1 动效层（反馈 / 定向 / 可发现性）

> 触发：用户按 `ui-animation` 技能要求「设计做好网站」。
> 前提：本站视觉规范（`02-视觉规范-瑞士编辑风.md`）明确 **零装饰、无滚动入场动画**，且历史上 `opacity:0` 入场初态在爬虫/截图/rAF 节流下让整块内容消失（`AGENTS.md`「常见坑」）。
> 所以这一层**不加入场动画**，只补三类有功能理由的动效：反馈、定向、可发现性。

---

## 1. 改了什么（改前 → 改后）

| 位置 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| 全站 13 条 `:hover` 规则 | 无条件生效 | 收进 `@media (hover: hover) and (pointer: fine)` | 触屏上 `:hover` 会在点完之后**粘住**，颜色残留成假选中态（按钮点完一直亮着） |
| 按钮 `.btn` / `.jn-btn` | 无按压反馈 | `:active { transform: scale(.98/.97) }`，90ms enter 曲线 | 手指按下去 90ms 内必须有变化，否则按钮像没响应 |
| 按钮 / 导航 | 无 `touch-action` | `touch-action: manipulation` | 去掉移动端 300ms 点按延迟 |
| 颜色过渡（13 处） | `120ms linear` | `200ms ease`（走令牌） | 颜色用 linear 读起来是机械的；120ms 对颜色太赶 |
| 顶栏按钮 `.jn-btn` | 完全没有过渡 | 显式 4 个属性过渡 + 按压 | 原来悬停是硬切 |
| 分类入口卡 `.cat-entry` | 只有文字变色 | `:active` 下沉 1px + 悬停时元信息行强调色线由左生长（`scaleX 0→1`，240ms） | 一张照片卡如果只有文字变色，用户不知道整张卡可点；**图不缩放**（照片要保持真实，且缩放会压到下方文字） |
| 分类锚点条 `.cat-index a` | 无过渡 | 颜色 200ms + `touch-action` | 7 段跳转的入口，反馈要跟手 |
| `html` | 锚点硬跳 | `scroll-behavior: smooth`（仅 `no-preference`） | 点第 6 类后要能看出"跳到哪一段"，硬跳丢空间上下文 |
| `prefers-reduced-motion: reduce` | 已有全局 kill switch | 保留，并把平滑滚动一起关掉 | 减少动效用户不该被滑动带走 |

**没有做的，以及为什么**

- 不做滚动入场 / 视差 / 数字滚动：违反视觉规范；且会重演 `opacity:0` 让内容"消失"的事故。
- 不做图片 hover 缩放：照片索引里缩放会把注意力从内容移到效果上，且需要额外 `overflow:hidden` 包裹（会干扰栅格）。
- 不给非交互元素（缩略图格、满幅照片）加动效：不可点的东西不该有 hover 反应。
- 视频区不动：`<video controls preload="none">` 用原生控件，加覆盖层只会和原生播放键打架。

## 2. 令牌（`src/styles/tokens.css`）

```css
--ease-enter: cubic-bezier(0.22, 1, 0.36, 1);  /* 入场 / 按压 */
--ease-move:  cubic-bezier(0.25, 1, 0.5, 1);   /* 位移 */
--dur-press: 90ms;
--dur-hover: 200ms;
--dur-underline: 240ms;
```

页面里不许再出现硬编码的 `cubic-bezier(...)` 或毫秒数；动效只动 `transform` / `opacity` / 颜色类属性，**没有** `transition: all`，**没有**布局属性过渡（`width/height/top/left`）。

## 3. 验收（`scripts/verify-motion.py`）

```bash
NODE_ENV=production PORT=3300 node dist/server.cjs
env -u PYTHONPATH python scripts/verify-motion.py --url http://127.0.0.1:3300/
env -u PYTHONPATH python scripts/verify-motion.py --url http://127.0.0.1:3300/projects
```

断言的是**会失败的东西**（读真实计算样式，不看截图）：

| 段 | 断言 | 2026-11-19 实测 |
|---|---|---|
| A | `scroll-behavior = smooth` | ✅ smooth |
| A | 按钮 `transition-property` 含 background-color / border-color / color / transform，且不含 `all` | ✅ 四项齐、无 all |
| A | 按钮与分类卡 `touch-action = manipulation` | ✅ |
| A | 悬停按钮底色**真的变**（`rgb(0,64,192)` → `rgb(0,48,143)`） | ✅ |
| A | 悬停分类卡下划线 `matrix(0…)` → `matrix(1…)` | ✅ |
| C | reduce 下 `scroll-behavior = auto`、按钮过渡 `0s` | ✅ |
| B | 移动指标 + 触摸模拟下 `matchMedia('(hover:hover) and (pointer:fine)')` 为 false，且悬停**不改**底色 | ✅ |

**探针两个坑（都踩过，别再踩）**

1. 本站锚点滚动是 smooth，`scrollIntoView()` 后**立刻**取 `getBoundingClientRect()` 拿到的是滚动前的坐标 → 鼠标落在别处，`:hover` 永远进不去，A 段两条红。必须等滚动停（或 `behavior:'instant'`）再量。
2. `Emulation.setEmulatedMedia` **不支持** `hover` / `pointer`（只支持 color-scheme / prefers-reduced-motion / forced-colors）。模拟触屏要用 `setDeviceMetricsOverride{mobile:true}` + `setTouchEmulationEnabled`，并且**先断言媒体查询真的翻了** —— 否则 B 段永远是绿的（假通过）。
3. 同理：A 段悬停没生效时，B 段要判「**无效**」而不是「通过」，并把无效计入失败。
